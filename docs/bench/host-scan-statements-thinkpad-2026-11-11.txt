4. Both engines over the gate's query sets (#180)

  burrmill-bench engine-sql <nest> <one file per statement>

In process, one client, each statement once for the answer and then five times timed, median
reported; DuckDB first, then Burrmill. DuckDB is set up as nuthatch set it up (read_parquet over
each table's file list, union_by_name) at eight threads with no memory limit; Burrmill has
BUDGET_MB and THREADS as given and no spill directory. The binary is bench-base but for the last run. Where a digest differs the rows differ in the
last digit of a float sum, and DuckDB's own digest for those statements changes between runs
(delegation_flows: f544.. then 07ee..).
