host-scan on the ThinkPad, 2026-11-11: what the scan side costs on the path nuthatch drives.

  burrmill-bench host-scan <nest> <queries.tsv>     STATEMENT_ROUNDS=0, ROUNDS=5 (the default)

base is main at 99f0ffb with the probe; all is the same with burrmill#267 (one footer cache for
local segments), #268 (file lists reused) and #269 (a scan charged as it opens segments). Each
nest ran base then all, twice, under one lock (c1, c2). 32 cores; the load average is at the head
of each run and was 64 to 100 throughout, from work that was not ours to stop, so read the pairs
and not the absolute times.

  alloc  ~/1165-corpus/graph-allocations-nest-next   1,924 segments   2,048 MB, 8 threads
  gate   ~/release-gate/alloc-nest                   6,753 segments   2,048 MB, 8 threads
  qos    ~/release-gate/qos-nest                    14,913 segments     704 MB, 4 threads

Three engines in one process. Each counts every table (a count reads nothing of a segment but its
footer): first/counts/cold is the process's first read of each footer, second/counts/cold is a new
engine's first pass with the page cache warm, third is the same metered. REBIND is register_facts
for every table again on the third engine. scan_peak_kb is from a counter patched into cancel.rs
for this measurement, which the probe as landed does not print; allocs is 0 without
--features alloc-stats.
